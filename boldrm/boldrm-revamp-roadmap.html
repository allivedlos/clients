What Changes

Right now, the site runs on several different tools stitched together — Webflow for the pages, Wized to connect them to data, MemberStack for logins, and Airtable and Zapier quietly doing the pricing math behind the scenes. That's part of why prices can look inconsistent from one page to the next. The new version brings everything into fewer, more reliable tools that we fully control — so there's one place to look when something needs fixing, not five.

Part of the appCurrentlyNew version
WebsiteWebflow + Wized→Next.js (a modern website framework)
Logins & user rolesMemberStack→Supabase (secure logins with built-in permissions per role)
DatabaseAirtable→Supabase (the new database)
Behind-the-scenes calculationsCustom code spread across the website→One central calculation engine, in Supabase
AutomationZapier (doing the core work)→Built directly into the app; Zapier kept only for email tasks
Photo uploadsDropbox→Dropbox — unchanged
Files the app createsDropbox→Supabase (only visible to the right people)
ContractsDropbox Sign→Dropbox Sign — unchanged
Email marketingMailerLite→MailerLite — unchanged
Why this matters for pricing specifically: today's price calculation is spread across four different files — one part doesn't even run, and one number doesn't match what it should. Bringing it into one place fixes the "wait, why did the price change" problem for good.

One Decision For You To Make: App or Website?

There are two ways to build this. One gives you a real, downloadable app for phones alongside the website. The other is a website that already works great on a phone — no download needed. Here's what each actually costs and involves, so you can choose with the full picture.

React Native (a phone app)Next.js (a website)
What you getOne build powers the website plus real iPhone and Android appsA website that works great on phones too — nothing to download
Ongoing hosting costStarts free, but grows to around $2,400/year once we're publishing updates regularlyAbout $240/year
Extra steps for updatesApple and Google both charge yearly fees and review every update before it goes live — that can take daysNone — an update is live the moment we publish it
Fit with our design planHarder to prototype with the design tools we're planning to useFits directly with the tools already planned for the Design phase
How the website feelsFine, but built phone-app-first, so the website can feel like an afterthoughtBuilt specifically to be a great website first
Phone-only featuresFull access — camera, push notifications, works with no internetUploads and everything else work fine in the browser, just no offline mode or app-store listing
Best fit whenYou want people to literally download an appPeople mostly need a fast, reliable tool in their browser — phone included
Recommendation
Next.js — the website route. Nothing agents or staff do today — getting a quote, tracking a project, signing a contract — needs a real app to work. They already use the dashboard through a browser. This route also skips roughly $2,400+/year in app-store costs, and fits neatly with how we're planning to design the screens. Hosting it costs a modest $240/year, but means nothing to maintain on a server — and every new piece we build gets its own private preview link the moment it's ready, so it can be checked before it goes live. If a real app becomes worth building later, it can be added without redoing this rebuild — both routes are built on the same underlying technology.

The 8 Phases

This project runs alongside other active work, so the calendar length below is an estimate, not a fixed date — plan on roughly 4–6 months start to finish, firming up once Phase 1 is underway. Phases 4 through 6 overlap and repeat per piece rather than running strictly one after another.

1
Discovery & BenchmarkMONTH 1

Document the current system end-to-end and compare it against the proposed stack — cost, risk, and what changes for the client day to day. This phase produces the proposal itself.

Key activities
  • Loom walkthroughs per role, transcribed and mapped
  • Review of the existing code to fully understand how pricing works today
  • Full inventory of every tool currently in use
  • Operational cost comparison
Deliverable: System documentation + client-facing proposal deck
2
Planning & ArchitectureMONTH 1

Turn what we learned into an actual technical plan — what the new database looks like, how each role gets access, and exactly how we'll move everything over without breaking anything.

Key activities
  • Finalize the tools: Next.js for the website, Supabase for the database and calculations
  • Design the database and who can see what, per role
  • Write the spec for one, single, reliable pricing calculator
  • Draft the plan for moving everything over safely
Deliverable: Architecture spec + data model
3
DesignMONTH 1–2

Screens for all three roles, built visually before any code — ported from the real flows captured in Phase 1, not redesigned from a blank page.

Key activities
  • Agent/Homeowner, Designer Staff, Admin screens
  • Calculator + estimate flow, contract flow
  • Responsive review — mobile and web from one design
Deliverable: Approved screens, ready to build against

Design tooling and any AI design agents/skills to lean on will be settled when we reach this phase.

4
Environment SetupMONTH 2

The one-time scaffolding that everything else builds on top of.

Key activities
  • Set up the code repository
  • Set up three versions of the database — for testing, review, and the live site
  • Set up hosting — a private preview link for every update, plus the live site
  • Set up automatic deployment, so updates go live safely
Deliverable: Working "hello world" deployed to all three environments
5
Build in ModulesMONTH 2–4

We build one piece at a time rather than everything at once — the Pricing Calculator, Logins & Roles, Visualizations, Contracts & Signing, and the Admin Dashboard. Each piece is tested and reviewed before we move to the next.

The loop, per piece
  • Build it
  • Put it somewhere you and we can both review it
  • Test it thoroughly
  • Make it live, then move to the next piece
Deliverable: Five working pieces, each signed off before the next starts

Which AI coding tools we lean on for the actual build will be settled once we're here.

6
Data MigrationMONTH 4–5

The riskiest phase. The numbers currently stored don't always match what the pricing formulas say they should — so this isn't a simple copy-paste. We double-check everything before it goes live, early enough to catch problems.

Key activities
  • Move all records from Airtable to the new database — tested first on a copy
  • Move every user account over safely
  • In-progress drafts and contracts carried over
  • Compare the new numbers against the old ones before anything goes live
Deliverable: Verified migration, diffed and signed off
7
LaunchMONTH 5

Cut over from the old platform to the new one, with a safety net in place.

Key activities
  • Parallel run alongside the old platform, if feasible
  • DNS / cutover execution
  • Rollback plan on standby
  • Client training session for Andrew's team
Deliverable: Live platform, old stack decommissioned
8
Post-Launch MonitoringMONTH 5–6

A defined window to catch what only shows up under real usage, before this becomes a standard support arrangement.

Key activities
  • Fast-turnaround bug watch, 2 weeks
  • Usage monitoring across all three roles
  • Backlog captured for a v2 cycle
Deliverable: Stable platform + formal support handoff
